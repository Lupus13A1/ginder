Ginder Backend Architecture
Firebase Setup Guide

A comprehensive step-by-step manual to migrate the Bauhaus-themed Ginder app from mock data to a live Firebase backend.

01 Project Initialization & CLI Setup

To connect your Flutter app to Firebase seamlessly, use the official FlutterFire CLI.

  1. Go to the Firebase Console and create a new project named "Ginder Campus". Disable Google Analytics for now to keep things simple.
  2. Install the Firebase CLI globally on your machine: 
    npm install -g firebase-tools
  3. Log in to your Google account via the terminal: 
    firebase login
  4. Activate the FlutterFire CLI: 
    dart pub global activate flutterfire_cli
  5. Inside your Ginder Flutter project directory (c:\Users\thana\Desktop\lerner_flutter\ginder), run the configuration command. This will automatically register your Android, iOS, and Web apps and generate the firebase_options.dart file. 
    flutterfire configure

02 Flutter Dependencies Setup

Add the necessary Firebase packages to your pubspec.yaml file by running these commands in your terminal: 

flutter pub add firebase_core firebase_auth cloud_firestore firebase_storage google_sign_in

Then, initialize Firebase in your lib/main.dart:

import 'package:firebase_core/firebase_core.dart';
import 'firebase_options.dart';

void main() async {
  WidgetsFlutterBinding.ensureInitialized();
  
  await Firebase.initializeApp(
    options: DefaultFirebaseOptions.currentPlatform,
  );
  
  // ... existing UI setup
  runApp(const GinderApp());
}

03 Authentication Setup

We need to enable both University Email login and Google SSO.

1. Email & Password

  • In the Firebase Console, go to Build > Authentication.
  • Click Get Started, then go to the Sign-in method tab.
  • Select Email/Password, enable it, and click Save.

2. Google Sign-In

  • In the same Sign-in method tab, click Add new provider and select Google.
  • Enable it, provide a support email, and save.
IMPORTANT FOR ANDROID: To make Google Sign-In work on Android devices, you must add your SHA-1 certificate fingerprint to the Firebase Project Settings. You can get this by running ./gradlew signingReport inside your android/ folder.

04 Cloud Firestore Database Schema

In the Firebase Console, go to Build > Firestore Database and click Create database (Start in Test Mode). Here is the NoSQL schema you need to build Ginder:

Collection: users

Stores the student profile data. Document ID should match the Firebase Auth UID. 

users/{uid}
{
  "uid": "abc123xyz",
  "name": "Thanathip A.",
  "nickname": "Art",
  "age": 21,
  "faculty": "Architecture & Design",
  "major": "Urban Planning",
  "year": "Year 3 (Junior)",
  "bio": "Coffee and studio all night.",
  "interests": ["Coffee", "Design", "Museums"],
  "photos": ["https://firebasestorage...", "https://firebasestorage..."],
  "isVerifiedStudent": true,
  "incognitoMode": false,
  "createdAt": Timestamp
}

Collection: swipes

Tracks interactions to prevent showing the same card twice and to detect matches. 

swipes/{swipeId}
{
  "fromUserId": "userA_uid",
  "toUserId": "userB_uid",
  "action": "LIKE" // or "PASS", "SUPER_LIKE",
  "timestamp": Timestamp
}

Collection: matches

Created securely via a Cloud Function or client logic when two users mutually "LIKE" each other. 

matches/{matchId}
{
  "users": ["userA_uid", "userB_uid"],
  "matchedAt": Timestamp,
  "lastMessage": "Hey! Nice to match.",
  "lastMessageTime": Timestamp,
  "unreadCount_userA_uid": 0,
  "unreadCount_userB_uid": 1
}

Subcollection: matches/{matchId}/messages

Stores the chat history for a specific match.

messages/{messageId}
{
  "senderId": "userA_uid",
  "text": "Wanna grab matcha at the library?",
  "timestamp": Timestamp,
  "isRead": false,
  "icebreakerTag": "ICEBREAKER" // Optional
}

05 Cloud Storage Setup

Go to Build > Storage and click Get Started. This is where student profile pictures will be uploaded.

Structure your buckets like this to keep it organized:

  • /profile_photos/{uid}/photo_1.jpg
  • /profile_photos/{uid}/photo_2.jpg

06 Security Rules Configuration

Update your rules to ensure students can only edit their own profiles but can read other public profiles. Paste this in the Rules tab of Firestore: 

rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    
    // Require authentication for all access
    function isAuthenticated() {
      return request.auth != null;
    }

    // Users can read any profile, but only write to their own
    match /users/{userId} {
      allow read: if isAuthenticated();
      allow write: if isAuthenticated() && request.auth.uid == userId;
    }

    // Users can only see and write matches they are part of
    match /matches/{matchId} {
      allow read, write: if isAuthenticated() && request.auth.uid in resource.data.users;
      
      // Messages within a match
      match /messages/{messageId} {
        allow read, write: if isAuthenticated() && request.auth.uid in get(/databases/$(database)/documents/matches/$(matchId)).data.users;
      }
    }
    
    // Users can only record their own swipes
    match /swipes/{swipeId} {
      allow read: if isAuthenticated() && request.auth.uid == resource.data.fromUserId;
      allow create: if isAuthenticated() && request.auth.uid == request.resource.data.fromUserId;
    }
  }
}
